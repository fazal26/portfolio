// THREE STANDARDS
// HELD ON EVERY PROJECT
01 / STANDARD

Accessibility

Production interfaces delivered to WCAG standards — built that way from the first component, not audited into compliance at the end. Semantic structure, keyboard operability, managed focus and contrast verified against real numbers rather than assumed.

It is the rarest of the three. Most frontend engineers have never had to hold the line on it. Prologis was built accessibility-first from the data model up.

WCAGSemantic HTMLKeyboard operabilityFocus managementContrast
02 / STANDARD

Testing

A standard set and held, not a list of tools. Unit and component coverage close to the code, end-to-end coverage on the flows that carry revenue, and a clear line about which belongs where — so the suite stays fast enough that people keep running it.

The same review standard applies to AI-generated code as to anything else. Nothing merges because a model wrote it confidently.

PlaywrightVitestJestReact Testing LibraryCypressEnzyme
03 / STANDARD

Design Systems

Shared component libraries documented in Storybook, with reusable UI architecture that holds products together as teams and surfaces multiply. The alternative is six versions of the same button and nobody certain which one is correct.

Consistency is cheaper to build in than to recover, and a documented library is how a team keeps it without a meeting.

StorybookShared component librariesReusable UI architecture
